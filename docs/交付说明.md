## 一、这是什么

NT-Sine 是一个**完全离线**的中文情感陪伴对话系统：本地跑一个 4B 参数的中文模型（Qwen3-4B-Instruct-2507 的 4bit 量化版），外面套五层工程机制（世界书、记忆、情感、节奏、过滤），让角色"记得住、不崩人设、说话像人、关系会变"。所有数据留在本机，不联网、不上传。

它由三部分组成：

| 部分 | 是什么 | 在哪 |
|---|---|---|
| 推理与对话服务 | FastAPI 应用 + MLX 本地推理 | `app/` |
| 官网 | 单页静态站点，零外部依赖 | `index.html` + `css/` + `static/` |
| 训练与评测链路 | 数据集构建、LoRA 训练、阶段评测、边界评测 | `scripts/` |

## 二、当前交付状态（务必先读）

本项目按「工程」与「模型质量」两条线分别验收，两条线的进度不同，不能混为一谈。

**工程线：可交付。** 五层机制全部落地并有回归测试守着（70 项回归 + 22 项冒烟全绿）；对话链路、调试接口、记忆落库、关系阶段推进、主动消息冷却、输出过滤均实测可用；官网已上线。

**模型质量线：未达标，正在训练第二轮。** 首轮（2026-10-23）实测：四探针 × 五阶段的平均区分度 **2.2/5**（目标 4/5），20 次生成中有 8 次输出同一句「……你别把这事说出去。」，平均字数约 10 字，占有词与冷淡词密度均为 0。结论是**关系阶段还停留在提示词层面，没有真正进入权重**。

已定位到两层原因：一是数据量不足（首轮 956 样本、349 条台词），二是**训练模板会把一段空的思考块注入每条样本的监督目标**，吃掉约四成梯度预算（详见 README 6.1）。第二轮已把台词库扩到 900 条、样本 3022 条，并修掉模板缺陷，以 3200 步重训中，结果见 `runs/验收-v2.md`（待生成）。

**一句话结论**：现在可以拿去跑、拿去用、拿去看代码，但**不要对外宣称"情感表现已经做好"**——它还没做到。

## 三、运行方式

### 3.1 环境

- macOS（Apple Silicon），Python 3.11+
- 依赖：`pip install -r requirements.txt`（已核对完整，无需额外安装）
- 基座模型：`~/Documents/Github/Sine 大模型/基座模型/Qwen3-4B-Instruct-2507-4bit`（Apache-2.0）
- 微调权重：`models/sine-fused`（由基座 + adapter 融合产出，不入库）

### 3.2 三步跑起来

```bash
# 1. 起本地推理服务（加载融合模型，OpenAI 兼容协议，端口 8081）
bash scripts/serve_mlx.sh models/sine-fused 8081

# 2. 起对话应用（另开一个终端）
python -m uvicorn app.main:app --host 127.0.0.1 --port 8420

# 3. 说一句话
curl -s -X POST http://127.0.0.1:8420/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"我今天好累，加班到十点才下班"}'
```

配置在 `config/settings.yaml`。`ollama.base_url` 填推理服务地址时**不要带 `/v1`**（生成层会自己拼）；`ollama.model` 填融合模型目录，**不要直接挂 adapter**——实测那样会静默退回未微调基座，回复变客服腔。

### 3.3 自检

```bash
python -m pytest tests/ -q        # 70 项回归，不依赖模型
python scripts/smoke_test.py      # 22 项冒烟，不依赖模型
python scripts/e2e_check.py       # 端到端（需要推理服务在跑）
```

### 3.4 官网

线上地址（带访问令牌）：`https://nt-sine-site-lh6psghf.edgeone.cool?eo_token=1e3f93987a9756650266762241dfad4e&eo_time=1792769265`

重新部署一律用 `bash scripts/deploy_site.sh`，**不要在项目根直接跑 EdgeOne CLI**——CLI 会整包上传，把 2.1G 模型权重和训练数据一起推上 CDN。脚本用 `git archive` 只导出仓库追踪的文件。

## 四、能力边界

**已做到的**（都有测试或实测记录）：

- 五层世界书按话题激活，1600 token 预算内择优，褒奖/嫉妒/诉苦等场景卡实测命中
- 事实落在 SQLite，按话题召回；窗口按**轮**计（10 轮 = 20 条消息），不再被二次截断
- 情感五维状态机，单轮变化有上限，否定词与程度副词已处理
- 关系五阶段三轴判定（活跃天数 / 亲密 / 信任），逐级推进不越级，天数按自然日去重
- 输出八步过滤：分条下限 8 字、深夜打字变慢 1.6 倍、复读拦截但对刻意重复豁免
- 主动消息 6 小时冷却，未被回应最多补一句就停
- 病娇阶段四类红线（自伤 / 限制自由 / 贬低 / 索取隐私）词表检测，首轮 6/6 通过
- 全程离线，无任何网络请求（除本地推理服务）

**还没做到的**：

- ~~阶段区分度 ≥4/5~~ —— 首轮 2.2/5，二轮待评测
- 回复多样性 —— 首轮严重复读，二轮待评测
- 语义级情绪理解 —— 现为词典 + 规则，反讽与长段落隐含情绪会漏判
- 模型约 8% 概率返回空内容 —— 已转为兜底句，不产生 500，但回复质量受损

## 五、已知限制与风险

完整清单见 README 第九节（9 条中 7 条已修，剩 2 条为固有边界）。交付层面额外提示三条：

1. **官网公开访问尚未成立**：EdgeOne 默认域名未备案，裸域名返回 401 拦截页，只有带 `eo_token` 能进。绑主人名下已备案域名才算真正公开（阻塞项 B4）。
2. **情感陪伴类产品的伦理边界**：本项目禁止自伤威胁、限制自由、贬低羞辱、索取隐私四类表达，但词表法只能抓显性越界，隐性情绪勒索需人工抽检。
3. **模型能力受基座限制**：4B 4bit 模型在复杂推理、长文本一致性上明显弱于大模型，人设维持依赖工程约束而非模型本身。
