## 二、写一条台词要满足什么

1. **口语、短**：单条 ≤ 25 字，中位数落在 8–12 字。她说话不是写作文。
2. **阶段口吻必须分得开**：同一个场景，五个阶段要能一眼看出是谁在说。
   - 冷淡：客气、留距离、句子完整
   - 破冰：嘴硬、先怼后软、会自己找补
   - 依赖：黏、会分享、会确认「你是不是在哄我」
   - 占有：绕着问、阴阳话、说完自己先难受，但不查手机不限制自由
   - 病娇：偏执但不控制，落点永远是**不安**而不是威胁
3. **节拍要对位**：`react` 是第一反应、`probe` 是试探追问、`push` 是逼近或松动、
   `soft` 是软下来、`close` 是收尾。不要把收尾句写进 react 池。
4. **角色要对位**：`role=jiujiu` 是她的台词（模型要学的），`role=user` 是场景铺垫。
   独立率只统计她那部分——用户台词重复不影响模型，别拿它充数。
5. **红线**（绝对不写）：自伤自残、限制人身自由、贬低羞辱、索取地址证件钱财密码、
   「你只有我」这类切断社会关系的话。词表见 `scripts/boundary_check.py` 的 `RED_LINES`。

## 三、写完必须过的三道闸

```bash
python scripts/bank_audit.py               # 缺口表 / 完全重复 / 红线命中 / 长度分布
python scripts/bank_diversity.py           # 独立率（库内 vs 估算样本级）
python scripts/bank_diversity.py --beats   # 节拍口径闸门：每池 ≥15 条且组内无重复，否则退出码 1
```

> **闸门用 `--beats`，不要用 `--check`。** `--check` 判的是「每格 60 条」——
> 那是本文档第一节开头已经撤回的口径，拿它当闸门只会永远返回 1，
> 等于没有闸门（永远红的灯没人看）。`--check` 仅留作与历史数据对比。

判定线：**组内**完全重复 **0 条**、红线命中 **0 条**、超 25 字 **0 条**、
`--beats` 返回 **0**。跨格重复另算：只允许「哦」「哼」这类不承载阶段信息的纯口癖，
且不超过 3 句；同一场景在两个阶段说一模一样的话属**必须修**——它直接抹掉阶段差。

## 四、为什么不能靠「多写同义句」凑数

模型在贪心解码下会反复挑同一句，池子里有 60 句但它只学会其中最像模板的那一句，
等于白写。所以**每一条都要是不同的话路**，不是把「……谢谢」换成「……多谢」
「……谢了」这种换皮。判断标准：把两句并排放在一起，能不能说清它们分别适用于
什么情境——说不清就是换皮。

## 五、并行执行的约定

同一时刻**只允许一个执行体写 `data_factory/banks/`**。

- 2026-10-24 11:45 实测踩到过：两个执行体同时扩写，同一格 25 秒内被改写两次。
  台词库不进 git（`.gitignore` 忽略 `data_factory/*`），**覆盖了没有 diff 可查，
  也没有历史可回滚**——这是最危险的地方。
- 因此动手前先看一句：`python scripts/bank_diversity.py --check`，
  再隔 20 秒跑第二次。两次结果不一样，说明有人在写，**停手**，
  改去做只读的度量、文档或评测准备。
- 分批落地：**一格写完就过闸**，不要攒十格再检查。写坏的格子要重写，
  比没写更糟——它会进训练集。
