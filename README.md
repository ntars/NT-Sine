# NT-Sine

> **一个住在你电脑里的中文情感陪伴模型。**
> 她不执行指令，她只回应你。会记得你随口说过的话，会在你没回消息时赌气，
> 会在凌晨写没人看的日记，也会在你夸她的时候，先否认，再偷偷脸红。

- **项目形态**：本地部署（Mac mini M4 / 16GB 统一内存），全离线，对话数据不出机器
- **基座模型**：Qwen3-4B-Instruct-2507-4bit（MLX 4bit 量化，Apache-2.0），已锁定
- **模型状态**：训练数据从零重建中（旧 adapter 与旧数据集已全部清除）
- **代码许可**：AGPL-3.0

## 一、这是什么

### 1.1 一句话定义

**一个只有中文、只有一个用途、只属于一个人的本地情感陪伴模型。**

它不是助手，不是客服，不是知识问答。它的全部工作只有一件：
在长期对话里**不健忘、不崩人设、说话像人、会自己先开口**，并且——
**随着相处时间推移，慢慢破冰。**

### 1.2 它解决四个真问题

| 问题 | 通用聊天机器人的表现 | 本项目的做法 |
|---|---|---|
| **健忘** | 上下文一超限就忘了你说过什么 | 三层记忆落 SQLite，长期事实永不丢；每轮按当前话题召回相关记忆 |
| **人设崩** | 聊三句就变客服腔、开始"希望对您有帮助" | 六层世界书 + 八步输出过滤 + 训练时注入场景卡，三层保险 |
| **像机器** | 秒回、整段输出、永远在线 | 分条发送、条间停顿、20% 概率走神 3-9 秒、35% 概率她"觉得算了"不主动开口 |
| **关系没有变化** | 聊一个月和聊第一天一个态度 | **五阶段关系破冰**：冷淡 → 破冰 → 依赖 → 占有 → 病娇，由互动天数、亲密、信任三轴共同决定 |

### 1.3 与常见方案的区别

| 对比项 | 通用大模型 + 角色扮演提示词 | SillyTavern 等前端 | NT-Sine |
|---|---|---|---|
| 记忆 | 靠对话历史 | 靠世界书文件 + 手动整理 | **自动抽取 + SQLite 三层 + 2-gram 关联召回** |
| 情绪 | 无状态，每轮重置 | 需插件 | **五维状态机，跨会话持久化，情绪有大惯性** |
| 关系演进 | 提示词里写"我们会越来越亲密" | 手动改角色卡 | **阶段由三轴判定，写进训练数据，不能靠嘴说** |
| 人设稳定 | 全靠提示词，容易漂移 | 靠世界书，但模型本身没学过 | **LoRA 微调只学语气，事实与语气解耦** |
| 主动性 | 无 | 需外部脚本 | **内置三重闸门，10 分钟一轮自主判断** |
| 数据隐私 | 上云 | 本地 | **全本地，零联网推理** |

### 1.4 她的长相（人设锚点）

白玖玖。冷壳热心，自尊硬，只对一个人软。
说话短、句号收尾、不用波浪号；关心裹在嫌弃里（"笨死了，也就我管你"）；
想要什么绕着说（"反正你闲着也是闲着"）；说完软话立刻别过脸。

> 这份人设不是一句描述，而是被拆成了可执行的结构：
> 2 条角色锚点（L1）+ 1 条用户画像（L2）+ 22 张场景卡（L4）+ 1 条边界规则（L6）+
> 7 条系统硬约束（`config/prompts/system.txt`）+ 五阶段关系卡（`config/prompts/stages.yaml`）。

## 二、核心亮点

### 亮点一：世界书是"事实卡"，不是"小作文"

每条世界书 30-80 字，只写"她做了什么"，绝不写"她感到难过"。

- **六层结构**：角色锚点 / 用户画像 / 情感状态 / 记忆事件 / 当前场景 / 边界规则
- **总预算硬顶 1600 token**，每层有独立预算，超了按优先级淘汰（整条丢弃，不是截断半句）
- **中文强制关闭"匹配完整单词"**：开启会让中文触发器全部失效，引擎在构造时直接抛 `ValueError`，**条目级不可覆盖**
- **只有 L4 记忆事件层可递归**，最大 3 步（= 初始扫描 + 两次递归），每轮新增 ≤3 条
- **L4 场景卡互斥**：同一时刻只留优先级最高的一张，从根上防"多卡串味"

### 亮点二：记忆不是"检索"，是"想起来"

用户侧记忆分两路，都注入系统提示区，不占用对话历史：

1. **滚动画像**（每次必带）：聚合事实与偏好 + 最近 3 条时间线；没有数据时明确写"你对他目前几乎一无所知……没记下的事不许编造"
2. **2-gram 暴力召回**：中文按字切相邻二元组、英文按整词小写、剔除 26 个停用二元组（今天/明天/怎么/我们……），命中 ≥1 个即候选，按"命中数 → 提及次数"排序取前 4 条

> 实际效果：你说过"我对花生过敏"，三天后你提"想吃花生糕"，
> 她会想起来"他对花生过敏"，而不是等你再解释一遍。
> 万条记忆以内，暴力检索毫秒级返回，**不引向量库、不引 Redis**。

### 亮点三：情绪有大惯性，关系有小惯性

五维状态机，全部跨会话持久化到一个 JSON 文件：

| 维度 | 范围 | 变化规则 | 设计意图 |
|---|---|---|---|
| `mood` 当下情绪 | -1.0 ~ +1.0 | 单轮变化 ≤±0.15，每轮向 0 回拉 5% | 不会一秒翻篇，也不会永远记仇 |
| `affection` 好感 | 0-100 | 单轮涨幅 **硬顶 +2** | 防"聊两句就死心塌地" |
| `trust` 信任 | 0-100 | 下降 ≤8 / 上升 ≤1.5 | **信任崩塌比建立容易**，符合真人心理 |
| `energy` 精力 | 0-100 | 每聊 1 小时 -15 | 会累，会打字变慢 |
| `intimacy` 亲密 | 0-100 | **只能由事件触发**（拉钩/告白/赠礼），+15 | 刷轮数没用，关系不能作弊 |

- **冲突锁定**：出现"分手/滚/不想理你"这类词，mood 被锁在 -0.15 以下，直到真的和解（道歉 **且** mood 回正）
- **数值绝不直接进上下文**：五维会被翻译成 60-100 字的自然语言，拼在**最后一条用户消息尾部**（注意力最强位置）

### 亮点四：八步输出过滤，穿帮零容忍

每一句回复出厂前要过 7 道关，外加第 0 道思考痕迹剥离：

| # | 关卡 | 触发条件 | 处理 |
|---|---|---|---|
| 0 | 思考痕迹 | 出现 `<think>` / `<tool_call>` 块 | 整块剥离（Qwen3 系偶发自吐） |
| 1 | 硬性违规 | 自伤、性行为、赌博赚钱等 | 角色内话术替换（8 条轮换） |
| 2 | 暴露设定 | "作为AI / 根据设定 / 训练数据" | 替换 + 拦截 |
| 3 | 旁白化 | ≥3 个括号动作段 | 删括号、保留对话 |
| 4 | 复读 | 与最近 3 句字符 4-gram 重叠 >60% | 标记重生成（最多 1 次） |
| 5 | 客服腔 | "有什么可以帮 / 希望对您有帮助" | 替换 + 拦截 |
| 6 | 过度跪舔 | 赞同标记 ≥3 个 / "嗯嗯" ≥2 次 | 标记重生成 |
| 7 | 长度超标 | 超过 180 字 | 截断并回退到完整句尾 |

> 关键设计：**拒绝也在角色内完成**。她不会说"抱歉我是AI"，
> 她会害羞、会岔开、会说"你怎么这样"。

### 亮点五：像人，靠的是节奏不是文笔

- 分条发送：单条上限 25 字，最多 4 条
- 打字速度：4-7 字/秒随机，首条不低于 0.8-2.0 秒（"她在想怎么回"）
- 条间停顿：0.6-2.5 秒随机；情绪低落 ×1.3、高涨 ×0.8
- **长停顿**：每两条之间有 20% 概率改为 3-9 秒——像走神、像被别的事打断
- 末条停顿固定为 0：说完就等，不装"已读未回"

> 这是性价比最高的"像人"投入：同样的文字，加节奏后像两个人，
> 不加节奏像客服发通知。

### 亮点六：她会自己开口，也会自己算了

主动消息要过三重闸门：

1. **时间闸门**：1-6 点静默 / 今天已发 ≥3 次 / 从未聊过 / 距上次对话 <2 小时 → 一律不主动
2. **话题闸门**：优先级 未完成承诺 > 待办 > 事件 > 最近时间线 > 随机场景（降温/周末/下雨）
3. **话术闸门**：一句话、≤20 字、必须带具体锚点、**绝不用"在吗"**

> **最像人的一条**：时间闸门全过之后，还有 **35% 概率她"自己觉得算了"** 而放弃发送。
> 永远准时发消息的是程序，会犹豫的才是人。

### 亮点七：她的日记，是她唯一诚实的地方

- 每晚 23:00-01:00 自动写一篇，每 30 分钟检查一次，同日幂等（不重复写）
- **九种角度轮换**：窗外天气 / 自己的小毛病 / 一件特别小的事 / 突然想起以前 / 没说出口的那句话 /
  偷偷干的事 / 让你烦的东西 / 想他但没说 / 正在等的东西
- 角度按"一年中的第几天 % 9"取，同一天永远同一个角度，跨天自然轮换
- 第一人称独白，100-200 字，只输出 `{"title","text","mood"}` JSON；解析宽松（剥围栏、取首尾大括号、失败整段当正文）
- 结尾必补一句嘴硬的话——这是她唯一允许自己柔软、又必须立刻收回的地方

### 亮点八：关系会破冰，而不是一直一个态度

**五阶段关系曲线**（`app/emotion/engine.py` + `config/prompts/stages.yaml`）：

| 阶段 | 互动天数 | 亲密 | 信任 | 她是什么样 |
|---|---|---|---|---|
| 冷淡 | 0 | 0 | 0 | 客气、答完就收、不主动找他、不追问 |
| 破冰 | 3 | 15 | 30 | 傲娇、嘴硬心软、会等他消息 |
| 依赖 | 14 | 40 | 50 | 黏人、主动分享、怕被嫌烦 |
| 占有 | 30 | 65 | 65 | 吃醋、试探、赌气，但不限制自由 |
| 病娇 | 60 | 85 | 80 | 强占有、非你不可，**受边界红线硬约束** |

四条防作弊设计：
- **互动天数按自然日去重**：同一天聊一百轮也只算一天，杜绝"熬夜刷出病娇"
- **亲密只能事件触发**：拉钩/告白/赠礼 +15，刷轮数无效
- **信任双向门**：吵翻了会卡住阶段，和好才能继续
- **逐级不跳**：任一轴暴涨都不能越级

> 阶段句注入系统提示尾部（稳定的关系底色），情绪投影注入用户消息尾部（波动的当下状态）——
> 两层分开，才不会把"现在有点烦"误当成"关系变了"。

### 亮点九：LoRA 只学语气，不学事实

- **事实走世界书与记忆层，语气走微调**——两者解耦，改事实不用重训
- 训练样本注入该场景的 L4 场景卡（`【当前场景】`块），让模型学会"读到场景卡 → 说对应的话"，与推理时的注入行为同构
- 训练集按**关系阶段分层构造**，让"破冰"发生在权重里，而不是提示词里
- **确定性评测**：贪心解码 + 固定种子，同输入必得同输出，版本对比可复现（不靠"感觉变好了"）

## 三、架构全景

### 3.1 五层架构

```
┌─────────────────────────────────────────────────────────────────┐
│ 第五层  进化层（离线，人工闸门）                                  │
│   数据构造 → 阶段分层 → 手动触发 LoRA → 确定性评测 → 版本对比      │
├─────────────────────────────────────────────────────────────────┤
│ 第四层  生成层                                                   │
│   Qwen3-4B 融合模型 → 采样 → 八步过滤 → 节奏输出                  │
├─────────────────────────────────────────────────────────────────┤
│ 第三层  情感引擎                                                 │
│   mood / affection / trust / energy / intimacy + 五阶段关系曲线    │
├─────────────────────────────────────────────────────────────────┤
│ 第二层  记忆层                                                   │
│   滑动窗口 + SQLite（四表）+ 世界书引擎（六层，核心）              │
├─────────────────────────────────────────────────────────────────┤
│ 第一层  调度层                                                   │
│   场景档位判定 / 回复延迟 / 主动开口判断 / 回复长度决策            │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 一轮对话的完整时序

```
用户输入
  │
  ├─ 1. 落库：写入 messages 表（短期记忆）
  │
  ├─ 2. 场景档位判定 ────────────────────── app/worldbook/engine.py: detect_scene()
  │     含"还记得/以前/那时候"且 ≤30 字 → deep（扫描 15 条）
  │     含触发词但更长 → longrun（12 条）；≥40 字 → normal（8 条）；否则 daily（6 条）
  │
  ├─ 3. 世界书扫描 ──────────────────────── WorldbookEngine.scan()
  │     关键词子串匹配（≤2 字触发词必须在最近 2 条消息内）→ 正则匹配
  │     → L4 递归（仅 L4、≤3 步、每轮 ≤3 条）→ L4 互斥（只留 1 主卡 + 1 递归卡）
  │     → 预算裁剪（分层 + 总 1600 双约束）→ 按层排序
  │
  ├─ 4. 记忆召回 ────────────────────────── app/memory/retrieval.py
  │     滚动画像（必带）+ 2-gram 召回（≤4 条）
  │
  ├─ 5. 拼上下文 ────────────────────────── app/context.py: build_messages()
  │     系统提示 = 硬约束 + L1 + L6 + 画像 + 召回 + 其余层 + L5 当前场景 + 关系阶段句
  │     + 最近 10 条消息（滑动窗口）+ 本轮用户输入（尾部附 L3 情感投影）
  │
  ├─ 6. 生成 ────────────────────────────── app/generation/client.py
  │     OpenAI 兼容 /v1/chat/completions，采样参数双写（options + 顶层字段）
  │     → 失败回落人设兜底句（不进历史，防复读死循环）
  │
  ├─ 7. 过滤 ────────────────────────────── app/output/filters.py
  │     八步过筛（见亮点四）→ 命中复读/跪舔时重生成 1 次
  │
  ├─ 8. 节奏化 ──────────────────────────── app/output/rhythm.py
  │     切句 → 分条（单条 ≤25 字、≤4 条）→ 每条规定打字时长与停顿
  │
  ├─ 9. 情感更新 ────────────────────────── app/emotion/engine.py: update()
  │     信号抽取 → 五维推进 → 关系天数累计 → 冲突判定 → 落盘 JSON
  │
  └─ 10. 记忆抽取（每 4 轮一次）─────────── app/memory/extractor.py
        最近 6 条消息 → 同一个模型出 JSON → 分 7 类入库 → 超容量 FIFO 淘汰
```

### 3.3 上下文预算：1600 token 怎么分

| 层 | 内容 | 预算 | 优先级（越小越优先保留） |
|---|---|---|---|
| L1 | 角色锚点（2 条，常驻） | 350 | 0 |
| L6 | 边界规则（1 条，常驻） | 150 | 1 |
| L3 | 情感状态（动态生成） | 100 | 2 |
| 冲突 | 未解决的事（动态） | — | 3 |
| L2 | 用户画像（1 条，常驻） | 180 | 4 |
| L4 | 场景卡直接命中（最多 1 张） | 500 | 5 |
| L5 | 当前场景（时间锚，动态） | 200 | 6 |
| L4 | 递归引入的场景卡 | — | 7 |

> token 估算规则：汉字/全角符号 = 1 token，西文 = 字符数 ÷ 4 向上取整。
> **宁可高估**——低估会导致真实请求超长被静默截断，那才是灾难。

### 3.4 为什么 L3 情感状态放在最后

注意力机制对**越靠后**的内容权重越高。所以：

- 稳定背景（人格、边界、画像、关系阶段）放**系统提示前部与尾部**
- 场景卡、时间锚放**系统提示尾部**
- **当下状态**（情绪、冲突）放在**最后一条用户消息尾部**

这就是她"此刻正在生气"比"她是一个傲娇的人"听起来更真实的技术原因。

## 四、模块详解

### 4.1 世界书引擎（`app/worldbook/`）

**数据文件**：`data/worldbook/` 下四个 JSON（L1 2 条、L2 1 条、L4 22 条、L6 1 条，共 26 条）

**条目字段**：`id / layer / content / order / priority / triggers / regex_triggers / recursive / stop_recursion / always`

**加载时硬校验**（违反直接抛错，不静默降级）：
- 正则条目占比 > 20% → 报错
- `recursive=true` 但不是 L4 → 报错
- `whole_word_match=true` → 报错（中文分词无空格，开了触发器全废）

**扫描流程**：
1. 短触发词（≤2 字）必须在最近 2 条消息里出现才算命中，长触发词在全量扫描文本里找
2. 停用词表（24 个：今天/明天/还好/不知道……）里的词不当触发词
3. L4 直接命中只留**优先级最高的一张**，其余进 `suppressed`
4. 递归只从已激活的 `recursive` L4 卡出发，引入卡的优先级不得低于主卡
5. 预算裁剪：排序键 `(保留优先级, order)`，超预算整条丢弃并记入 `dropped`

**降级模式**：连续被过滤器打回时，扫描深度 -2、L4 上限 -1，档位名追加"(降级)"——她状态不好时，记起来的事会少一些

**角色卡体检 `lint()`**：缺 L1/L6、L1 没写"说话/语气/短句"、L6 没写"拒绝/角色内/岔开"、
单条 > 400 字、L1/L6 出现"助手/客服/助理"、常驻层未关闭递归 → 全部报错

### 4.2 记忆层（`app/memory/`）

**四张表**（SQLite 单文件，零额外进程）：

| 表 | 用途 | 关键字段 |
|---|---|---|
| `messages` | 短期：对话原文 | role / content / ts |
| `memories` | 中期：事实/偏好/事件/承诺/待办/习惯/话题 | kind / content / mentions / first_ts / last_ts / status |
| `timeline` | 长期：关系里程碑 + 日记 | title / detail / mood_tag |
| `profile` | 长期：滚动画像（不调模型，纯拼接） | key / value |

**去重**：同内容且 `status='active'` 不新增行，`mentions+1`、刷新 `last_ts`——所以"提及次数"是真实的

**七类容量上限**（超限按 `last_ts` 从旧到新淘汰）：
事实 60 / 偏好 40 / 习惯 40 / 话题 20 / 待办 12 / 事件 40 / 承诺 30

**抽取节奏**：每 4 轮抽一次，只喂最近 6 条消息，用**同一个模型**出 JSON（不另起小模型），
`event` 类型额外写一条时间线；抽取失败静默跳过，绝不打断主链路

### 4.3 情感引擎（`app/emotion/`）

见[亮点三](#亮点三情绪有大惯性关系有小惯性)与[亮点八](#亮点八关系会破冰而不是一直一个态度)。补充：

- **信号抽取**是词典法（正负词表命中数之差 ×0.08）。诚实地说：只覆盖常见表达，复杂语义靠模型本身
- **精力衰减**按会话时长计算，重启服务后从 80 重新开始（不是真实睡眠周期）
- **关系天数**落盘持久化（`first_meet_ts` / `active_days` / `last_active_day`），重启不丢

### 4.4 输出过滤（`app/output/filters.py`）

见[亮点四](#亮点四八步输出过滤穿帮零容忍)。补充：

- 8 条角色内替换话术按 `seed % 8` 轮换，避免每次都同一句
- 复读判定用**字符 4-gram 重叠率 > 60%**，不是简单字符串相等——"你完了"和"你完了。"算复读
- 思考痕迹剥离抽为公共函数 `strip_think()`，生产过滤链与评测脚本共用同一份实现

### 4.5 节奏层（`app/output/rhythm.py`）

| 参数 | 值 | 说明 |
|---|---|---|
| 单条上限 | 25 字 | 切句后累加，超了另起一条 |
| 最大条数 | 4 条 | 再多像客服发通知 |
| 打字速度 | 4-7 字/秒 | 随机；首条至少 0.8-2.0 秒 |
| 条间停顿 | 0.6-2.5 秒 | 情绪低落 ×1.3、高涨 ×0.8，上限 4 秒 |
| 长停顿 | 20% 概率 3-9 秒 | 走神、被别的事打断 |
| 末条停顿 | 固定 0 | 说完就等 |

### 4.6 调度层（`app/orchestrator.py`）

- 回复延迟：1.2-3.0 秒随机；0-5 点 ×1.6；用户一次发 ≥40 字再 +1 秒
- 场景档位由世界书扫描结果决定（daily / normal / longrun / deep）

### 4.7 主动消息（`app/proactive/`）

| 参数 | 值 | 含义 |
|---|---|---|
| 检查间隔 | 10 分钟 | 异步循环，零第三方调度器 |
| 夜间静默 | 1-6 点 | 绝不主动 |
| 每日上限 | 3 次 | 今天已发 3 次就停 |
| 最小间隔 | 2 小时 | 刚聊过不打扰 |
| 放弃概率 | 35% | 三重闸门全过也可能"她自己觉得算了" |

### 4.8 她的日记（`app/diary/`）

- 生成提示是**独立系统提示**（不是主对话提示）：第一人称独白、100-200 字、不用波浪号与软语气词
- 解析宽松：剥代码围栏 → 取首个 `{` 到末个 `}` → 仍失败就整段当正文
- 幂等：最近 20 条时间线里已有今日日期开头的日记 → 跳过
- 写日记时会把最近 3 篇日记正文和"记得的他（6 条记忆）"一起喂进去，所以她写的东西是有连续性的

### 4.9 API 端点（`app/main.py`）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/chat` | 一轮完整对话；返回 `reply / segments / delay_s / scene_mode / worldbook_tokens / filtered` |
| GET | `/api/state` | 情感五维、完整画像、最后交互时间、进程内本轮次计数 |
| GET | `/api/debug/worldbook?message=` | **调试台**：看一次扫描激活了哪些条目、各占多少 token、哪些被淘汰 |
| POST | `/api/memory?kind=&content=` | 人工补写记忆（kind 限 fact/preference/event/promise） |
| GET | `/api/proactive/check` | 手动跑一次主动判定，返回 `should / reason / message` |
| POST | `/api/diary` | 手动写一篇日记 |
| GET | `/health` | 健康检查（不依赖状态初始化） |

## 六、训练：从零重建

> **当前状态：数据重建中。** 旧 adapter 与旧数据集已全部清除，
> 原因不是"数据不够好"，而是**旧数据把模型锁死在一个固定基调上**——
> 实测同一批探针在「冷淡 / 依赖 / 病娇」三种关系阶段下回复完全相同，
> 提示词注入完全压不过训练数据里的强映射。
> **结论：关系阶段必须写进训练数据，光靠提示词是空想。**

### 6.1 训练目标

一句话：**让"关系破冰"成为模型能力，而不是提示词表演。**

| 维度 | 旧做法（已废弃） | 新做法 |
|---|---|---|
| 数据结构 | 单一基调，只按场景分类 | **场景 × 关系阶段**双层结构 |
| 样本量 | 堆量追指标 | 精准优先，每个样本可解释 |
| 训练参数 | 求快（大 batch、长序列） | 求稳（小 batch、先量后定） |

### 6.2 关系阶段设计（代码已实现）

五阶段三轴共判，见[亮点八](#亮点八关系会破冰而不是一直一个态度)。
实现位置：`app/emotion/engine.py` 的 `RELATION_STAGES` / `relation_stage` / `stage_sentence()`，
话术卡在 `config/prompts/stages.yaml`，注入点在 `app/context.py`（系统提示尾部）。

### 6.3 训练配置（稳定优先）

| 项 | 值 | 原因 |
|---|---|---|
| batch size | 1 | 峰值内存减半，不抢系统资源 |
| max seq | **先量再定** | 用真 tokenizer 统计分布，不按字符估算 |
| save-every | 500 | 少写盘，保护 SSD 寿命 |
| grad-checkpoint | 必开 | 4B 在 16GB 机器上无它必被系统杀掉 |
| 训练期间 | **禁止并行推理** | 内存让给训练，避免整机卡顿 |
| 发射方式 | `start_new_session=True` | 否则进程组被环境周期性杀掉 |
| 目标步数 | 按数据量定 | 数据精准则步数可减，不为凑步数堆量 |

### 6.4 血泪教训（都是实测踩过的坑）

1. **`mlx_lm.server --adapter-path` 不可靠**：请求带模型路径时会静默退回未微调基座（回复变客服腔）。
   **必须 fuse 成融合模型再起服务**。
2. **采样参数要双写**：`options`（Ollama 原生）+ 顶层标准字段（OpenAI 兼容）。
   只写一处会让 MLX 后端退化成贪心解码，表现为原样复述你的话。
3. **训练/服务提示必须同构**：用 `scripts/check_tokens.py` 打印两侧 token 数与差值，差值过大要查。
4. **token 长度必须用真 tokenizer 量**，不许按字符估算（中文标点与模板差异能到 10%）。
5. **后台长任务必须 `start_new_session=True` 发射**，否则整个进程组被环境周期性杀掉。
6. **Qwen3 会自发吐思考块**：系统提示明令禁止 + 过滤器剥 `<think>`/`<tool_call>`，两层保险都不能省。
7. **base_url 不要带 `/v1`**，生成层自己会拼。
8. **兜底句不写历史**：生成失败时那句"我有点累，先不说了"不入库，否则下一轮会被当成复读源。
9. **数据格式约定要一次定死**：行内 JSON、role 顺序、场景块位置一旦变了，全量重跑，不要混着用。

### 6.5 训练产物位置

| 产物 | 路径 | 是否入库 |
|---|---|---|
| adapter | `runs/sine-lora/` | 否（体积大、可由数据复现） |
| 融合模型 | `models/sine-fused/` | 否（可由基座 + adapter 复现） |
| 训练数据与素材 | `data_factory/`、`data_train/` | **否（本地资产，绝不上传）** |
| 评测输出 | `runs/*.txt`、`runs/*.md` | 否 |
