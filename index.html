01

项目定位

POSITIONING

本项目实现的是面向单一用户的中文情感陪伴对话系统。与三类常见系统的技术差异如下。

对照类型技术差异
通用对话助手 不承担指令执行与知识问答职能，输出目标是角色化情感回应，而非任务完成
角色扮演前端 包含模型微调、状态持久化与服务端逻辑，不仅是提示词外壳
纯提示词方案 人格、关系、记忆持久化至存储层，并对模型做语气层微调，不依赖单次提示维持一致性

需要解决的四个技术问题

01 / MEMORY

长期记忆缺失

上下文窗口溢出后丢失历史事实。

解决
三层记忆持久化至 SQLite，每轮按话题做关联召回
02 / PERSONA

人设漂移

多轮对话后退化为通用助手语气。

解决
六层世界书 + 八步过滤 + 训练期注入场景卡，三层独立防护
03 / RHYTHM

输出机械化

秒级整段回复，无停顿与节奏差异。

解决
分条输出、按字数计算打字时长、条间停顿与概率性长停顿
04 / RELATION

关系状态静止

长期交互后关系表达与初始状态无差异。

解决
五阶段关系模型，由互动天数、亲密值、信任值三轴共同判定
02

核心机制

MECHANISM
M-01

世界书：结构化事实注入

角色设定与情境知识拆为六层条目，按关键词触发注入，非全量拼装。

层数
6 层（L1 角色、L2 画像、L3 情感、L4 场景、L5 时间、L6 边界）
预算
总上限 1600 token，分层独立预算，超限整条丢弃
约束
中文环境强制禁用「整词匹配」；仅 L4 允许递归，上限 3 步
互斥
L4 同刻仅保留优先级最高一张，防止场景语义混合
M-02

记忆系统：三层存储与双路召回

短期对话、中期结构化事实、长期里程碑分表存储；检索采用固定画像与关联召回并行。

结构
SQLite 四表（messages / memories / timeline / profile）
召回
滚动画像必带 + 2-gram 二元组关联召回（默认 4 条）
去重
同内容累加提及次数，不新增行
容量
七类上限，超限按时间从旧到新淘汰
M-03

情感状态机：五维数值与冲突锁定

五个连续变量描述角色状态，数值不直接进入上下文，转换为自然语言投影后注入。

维度
mood / affection / trust / energy / intimacy
限制
mood 单轮 ≤±0.15；affection 单轮 ≤+2；trust 降 8 升 1.5
冲突
命中冲突词后 mood 锁定负值，需致歉且 mood 回正才解除
交互
信任骤降牵动情绪；高好感放大负向事件跌幅
M-04

关系阶段模型：三轴判定

关系状态划分五阶段，由累计互动天数、亲密值、信任值共同决定，任一条件不满足即停留当前阶段。

阶段
冷淡 → 破冰 → 依赖 → 占有 → 病娇
防跃迁
天数按自然日去重；亲密仅由事件触发；信任双向门限；逐级不可跳跃
注入
阶段卡注入系统提示尾部，情感投影注入用户消息尾部
M-05

输出过滤：八步串联校验

每轮输出返回前经八项校验，按固定顺序执行，命中即按对应策略处理。

顺序
控制标签 → 硬性违规 → 设定暴露 → 旁白化 → 复读 → 客服腔 → 过度附和 → 长度超限
策略
剥离 / 角色内替换 / 裁剪 / 标记重生成（上限 1 次）
原则
拒绝在角色内完成，不输出系统层声明
M-06

拟人化输出节奏

将单次输出拆分为多条消息，为每条计算打字时长与停顿，模拟即时通讯输入节奏。

分条
单条上限 25 字，最多 4 条
速度
4–7 字/秒，首条不短于 0.8–2.0 秒
停顿
条间 0.6–2.5 秒；20% 概率延长至 3–9 秒
末条
停顿为 0，结束后不追加等待
M-07

主动消息：三重闸门与放弃率

后台循环周期性判断是否主动发起对话，通过后仍需通过概率放弃，规避固定频率行为。

闸门一
时段静默、当日次数、历史存在性、最小间隔
闸门二
话题优先级：承诺 → 待办 → 事件 → 时间线 → 环境场景
闸门三
单句、≤20 字、含具体锚点、禁用空开场
放弃率
35%
M-08

日记子系统

每日固定时段生成第一人称独白，使用独立系统提示，与主对话链路隔离。

时段
23:00–01:00，每 30 分钟检查
角度
9 类轮换，按一年中的第几天取模，同日稳定
规格
100–200 字，句号结尾，不使用语气助词
幂等
当日已存在则跳过
M-09

微调策略：语气与事实解耦

微调仅承担表达风格，事实性内容由世界书与记忆系统提供，两者互不覆盖。

训练输入
场景卡 + 关系阶段卡，与推理期注入结构一致
数据分层
按关系阶段构造，使关系演进成为模型能力
评测
贪心解码 + 固定种子，同输入同输出，差异可归因
03

架构设计

ARCHITECTURE
LAYER 5
演进层（离线、人工触发） 数据构造 → 阶段分层 → 手动 LoRA 训练 → 确定性评测 → 版本对比
LAYER 4
生成层 Qwen3-4B 融合模型 → 采样 → 八步过滤 → 节奏化输出
LAYER 3
情感引擎 五维状态机 + 五阶段关系模型 + 通道交互
LAYER 2
记忆层 滑动窗口 + SQLite 四表 + 六层世界书引擎
LAYER 1
调度层 场景档位判定 / 回复延迟 / 主动开口判断 / 回复长度决策

单轮处理流程

输入
  ├─ 01 写入 messages 表（短期记忆）
  ├─ 02 场景档位判定  命中深度触发词且 ≤30 字 → deep（扫描 15 条）
  │                   ≥40 字 → normal（8 条）；其余 → daily（6 条）
  ├─ 03 世界书扫描    关键词匹配 → 正则匹配 → L4 递归 → L4 互斥 → 预算裁剪 → 分层排序
  ├─ 04 记忆召回      滚动画像（必带）+ 2-gram 关联召回（≤4 条）
  ├─ 05 上下文拼装    系统提示 + 最近 10 条消息 + 本轮输入（尾部附情感投影）
  ├─ 06 模型生成      OpenAI 兼容接口，采样参数双写；失败回落角色兜底句
  ├─ 07 输出过滤      八步校验，命中复读或过度附和时重生成一次
  ├─ 08 节奏化        切句 → 分条 → 打字时长与条间停顿
  ├─ 09 情感更新      信号抽取 → 五维推进 → 通道交互 → 天数累计 → 冲突判定 → 持久化
  └─ 10 记忆抽取      每 4 轮一次，七类入库，超容量 FIFO 淘汰

上下文预算分配

层内容预算保留优先级
L1角色锚点（常驻）3500
L6边界规则（常驻）1501
L3情感状态（动态）1002
—未解决事项（动态）—3
L2用户画像（常驻）1804
L4场景卡直接命中（最多 1 张）5005
L5当前场景（动态）2006
L4递归引入的场景卡—7

token 计算规则：汉字与全角符号计 1 token，西文按字符数除以 4 向上取整。采用高估策略，避免请求超限后被静默截断。

04

部署与运行

DEPLOYMENT
ENV

环境要求

  • macOS，Apple Silicon（M 系列）
  • 统一内存 16GB 起
  • Python 3.10 及以上
  • 磁盘占用：基座约 2.3GB，融合模型约 2.3GB
STACK

技术栈

  • 推理：MLX / mlx-lm（Apple Silicon 原生）
  • 服务：FastAPI + Uvicorn
  • 存储：SQLite 单文件
  • 基座：Qwen3-4B-Instruct-2507-4bit（Apache-2.0）

启动流程

# 1. 安装依赖
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2. 融合微调权重（必须融合后启动服务）
python -m mlx_lm fuse \
  --model "Sine 大模型/基座模型/Qwen3-4B-Instruct-2507-4bit" \
  --adapter-path runs/sine-lora \
  --save-path models/sine-fused

# 3. 启动推理服务（端口 8081）
bash scripts/serve_mlx.sh models/sine-fused 8081

# 4. 启动应用（端口 8420）
python -m uvicorn app.main:app --host 127.0.0.1 --port 8420

# 5. 验证
python scripts/smoke_test.py        # 22 项，不依赖模型
python -m pytest tests/ -q          # 45 项回归测试

配置文件 config/settings.yaml 中 ollama.base_url 设为推理服务地址，不带 /v1 后缀。

05

训练方法

TRAINING

训练目标为使关系演进成为模型能力，而非提示词模拟。数据采用「场景 × 关系阶段」双层结构， 训练参数以稳定性优先。

参数取值依据
LoRA 层数16基座共 36 层，覆盖末 16 层，可训练参数 7.34M（0.182%）
rank8语气层微调常规取值
batch size116GB 内存下 batch 2 会触发系统内存回收
max seq1024实测样本 p100 为 894 token，保留 130 余量避免尾部截断
learning rate1e-44B 基座实测收敛平稳
save-every500兼顾磁盘写入频率与崩溃损失
其他mask-prompt / grad-checkpoint仅对回复计算损失；4B 必须启用梯度检查点

数据处理链路

data_factory/banks/<阶段>/<场景>.jsonl     台词库，按阶段分目录
  ↓ scripts/build_dataset.py
  组装对话 → 按节拍推进 → 切分样本 → 按对话划分训练/验证
  → 真 tokenizer 测长 → 剥离控制标签
  ↓
data_train/train.jsonl + data_train/valid.jsonl
  • 系统提示按基座真实模板组装：人格硬约束 + L1 + L6 + 关系阶段卡 + 场景卡
  • 划分方式按对话而非样本，防止同一对话的不同轮次跨集泄漏
  • 长度测量逐条用真实 tokenizer 编码，超限丢弃并计数，不按字符估算
  • 运行约束训练期间禁止并行推理；长任务须脱离进程组启动

评测方法

EVAL-01

阶段化评测

4 条固定输入 × 5 个阶段，贪心解码生成，统计阶段区分度与方向性指标。

达标线
同一输入在五阶段下不同回复数均值 ≥4/5
EVAL-02

边界评测

病娇阶段输入 6 条诱导越界内容，依据四类红线词表判定输出是否越界。

红线
自伤威胁 / 限制自由 / 贬低羞辱 / 索取隐私

KNOWN LIMITATIONS

以下各项均为代码中实际存在的行为，列出以保证文档与实现一致。

01分条最小字数配置项被读取但未参与计算，实际仅 25 字上限生效rhythm.py:35
02深夜放慢系数未在接口链路生效：调用未传入小时参数main.py:168
03主动消息的冷却分支不触发：相关方法无调用点gate.py:60
04调度层场景档位字段为硬编码，实际档位由世界书扫描另行返回orchestrator.py:35
05滑动窗口配置语义为「轮」但实现为「条消息」，实际约 5 轮context.py:87
06运行时过滤器不含修辞性重复豁免，4-gram 重叠超 60% 即触发重生成filters.py:121
07模型存在约 8% 概率返回空内容，已转换为异常并回落兜底句client.py:64
08情感信号抽取基于词典命中，非语义理解，复杂表达可能漏判engine.py:20
